# Защита PostgreSQL: переход с `trust` на `scram-sha-256`

> Документ фиксирует выполненное изменение конфигурации СУБД (раздел ПП ПМ04
> «защита программного сервера» и ПП ПМ11 «защита базы данных»).

## 1. Исходное состояние (обнаружено при аудите)

| Параметр | Значение | Риск |
|---|---|---|
| `pg_hba.conf` | `local/127.0.0.1/::1 → trust` | любой локальный процесс подключался к БД под любой ролью, включая суперпользователя, **без пароля** |
| `pg_hba.conf` | `host all all 0.0.0.0/0 md5` | БД принимала подключения из локальной сети |
| `listen_addresses` | `*` | PostgreSQL слушал все сетевые интерфейсы |
| пароль роли `AST` | не задан | после включения парольной аутентификации администрирование стало бы недоступным |

## 2. Выполненные изменения

1. Роли суперпользователя `AST` задан пароль (хранится только в локальном `.env`).
2. `ALTER SYSTEM SET listen_addresses = 'localhost'` — сервер слушает только петлевой интерфейс.
3. `ALTER SYSTEM SET password_encryption = 'scram-sha-256'` — новые пароли хранятся в виде SCRAM.
4. В `pg_hba.conf` метод `trust` заменён на `scram-sha-256` для `local`, `127.0.0.1/32` и `::1/128`.
5. Строка `host all all 0.0.0.0/0 md5` удалена — удалённые подключения запрещены.
6. Записи для репликации закомментированы — репликация не используется.
7. Перед изменением сделаны резервные копии: `D:\PostDOP\*.bak-ГГГГММДД-ЧЧММСС`.

## 3. Результат проверки

```text
# прослушиваемый адрес
TCP    127.0.0.1:5432    0.0.0.0:0    LISTENING

# без пароля
psql: error: connection to server at "127.0.0.1", port 5432 failed:
      fe_sendauth: no password supplied

# с паролем
ht_app|scram-sha-256

# параметры сервера
AST|localhost
```

`GET /api/health` после изменения продолжает отвечать `status: ok`
(Prisma использует строку подключения с паролем роли `ht_app`).

## 4. Как подключаться теперь

```powershell
$env:PGPASSWORD = '<пароль из .env>'
& 'D:\post\18\bin\psql.exe' -h 127.0.0.1 -U ht_app -d habit_tracker
```

Приложение и скрипты берут пароли из `.env`; в коде и в git секретов нет.

## 5. Откат

```powershell
Copy-Item 'D:\PostDOP\pg_hba.conf.bak-<метка>' 'D:\PostDOP\pg_hba.conf' -Force
Restart-Service 'postgresql-X64-18' -Force
```

## 6. Что осталось сделать на этапе развёртывания

- включить SSL (`ssl = on`, сертификат) либо оставить соединения локальными;
- ограничить права суперпользователя: административные операции выполнять отдельной ролью;
- настроить `pg_stat_statements` и журналирование медленных запросов;
- хранить пароли не в `.env`, а в секрет-хранилище (для учебного стенда допустимо `.env`).
